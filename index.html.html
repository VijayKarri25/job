📝 Resume & Job Hunt

  • Action Verbs: Don't say "Did a project". Say "Implemented REST APIs", "Resolved database N+1 issues". Verbs show ownership.

  • ATS Friendly: Don't use heavy graphics, tables, or weird fonts. Applicant Tracking Systems parse plain text. Standard templates win.
  • Links: Include LinkedIn, GitHub, and a live link if deployed (e.g., Render, Railway). A live link proves you can deploy.
Scenario: "I have no projects" Build a "Task Management API" (Spring Boot + JWT + MySQL). Write unit tests. Deploy to Render/Railway for free. Put the live link on your resume.

🥷 Imposter Syndrome

Feeling like you don't belong or everyone is smarter than you. Extremely common in tech.

Reality Check You were hired because a team of professionals reviewed your skills and said "Yes". You are not a fraud. You are a junior; you are *expected* to not know things.
  • The "I don't know YET" rule: Change "I don't know this" to "I don't know this *yet*, but I will figure it out." It shifts your brain from fixed to growth mindset.
  • Don't compare: Don't compare your day 1 to a senior's year 5. Compare yourself to yourself 6 months ago.
  • Track wins: Keep a private "Brag Document". Write down every bug you fix and feature you ship. Read it when you feel low or before performance reviews.

⏳ Time Management

  • Pomodoro: 25 mins focus, 5 mins break. Stops you from burning out staring at a screen for 3 hours straight without moving.
  • Context Switching: It takes 15+ mins to regain deep focus after a Slack ping. Turn off notifications when doing deep logic work.
  • Calendar Blocking: Block 2 hours of "No Meeting" time daily. Treat it like a meeting with the CEO—unchangeable.
  • Eat the Frog: Do the hardest/most annoying task first thing in the morning when your willpower is highest.
Scenario: Manager interrupts constantly Say: "I'm in the middle of debugging a complex flow. Can I get back to you in 45 mins?" Or update your Slack status to "Deep Work until 2 PM".

⚡ CRUD Operations Deep Dive

  • Create (POST): @PostMapping. Accept JSON body (DTO). Call repository.save(entity). Return 201 Created (not 200 OK) with a Location header pointing to the new resource.
  • Read (GET): @GetMapping("/{id}"). Use repository.findById(id). Handle Optional properly using .orElseThrow() to return a 404. Never return null to the frontend.
  • Update (PUT/PATCH): Fetch existing entity first. Update fields. Call repository.save(). (PUT replaces all fields; PATCH updates only provided fields).
  • Delete (DELETE): @DeleteMapping("/{id}"). Call repository.deleteById(id). Return 204 No Content (no response body).

🛡️ Input Validation

  • Bean Validation (JSR 380): Add spring-boot-starter-validation. Never trust client-side validation alone; backend is the source of truth.
  • Annotations: @NotNull, @Size(min=2, max=50), @Email, @Pattern(regexp="...").
  • Controller Logic: Add @Valid before DTO. Add BindingResult immediately after to catch errors. Return 400 Bad Request if errors exist.
  • Custom Validators: Create @Constraint annotations for complex logic (e.g., "Password must contain special char and number").

📂 File Upload & Download

  • Config: spring.servlet.multipart.max-file-size=10MB.
  • Upload: @RequestParam("file") MultipartFile file. Use file.transferTo(new File(path)) locally.
  • Cloud Storage: Never save to local disk in production (loses data on restart/pod scale). Use AWS S3 SDK or MinIO.
  • Download: Read as Resource. Set Content-Disposition: attachment header to force browser download.
  • Security: Validate file extension (e.g., only .pdf, .png) to prevent uploading malicious scripts (.jsp, .exe) that could execute on the server.

🐳 Docker Basics

  • Image vs Container: Image is the blueprint (read-only). Container is the running instance (writable layer on top).
  • Dockerfile: Text file with instructions to build an image (e.g., FROM openjdk:21, COPY target/app.jar).
  • Commands: docker ps (running), docker logs -f [id] (follow logs), docker build -t myapp ..
  • Compose: docker-compose up -d to run multi-container apps (App + MySQL) in the background.
  • Volumes: -v mydata:/var/lib/mysql to persist DB data outside the container lifecycle.

🌿 Git Workflow

  • Branching: Never commit to main. Create feature branches: feature/ticket-123-login.
  • Commit Msg: "Fix login null pointer on user submit" (Good). "Fix bug" (Bad).
  • Commands: git stash (temp save), git fetch --all (sync remote without merging).
  • Merge vs Rebase: Rebase keeps history linear (clean), but rewrites history. Use Rebase on local feature branches, Merge on long-lived branches like develop.

🐛 Debugging Mastery

  • Breakpoints: Conditional (id == 500—stops only for that user). Logpoint (prints to console without stopping execution).
  • Remote Debugging: Connect IDE to server (port 5005). Add -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 to JVM args.
  • Evaluate Expression: Run custom Java code (e.g., user.getName().length()) while paused to test theories without changing code.

📖 API Documentation

  • SpringDoc: springdoc-openapi-starter-webmvc-ui. Auto-generates spec from code.
  • Annotations: @Operation(summary = "Get user"), @Parameter, @ApiResponse(responseCode = "404").
  • Why it matters: Frontend team relies entirely on this. If your Swagger is wrong or missing, you block them. Keep it updated.

📝 Logging 101

  • NEVER System.out.println: It's synchronous, blocks the thread, has no timestamp/level, and can't be filtered in production. Use SLF4J.
  • Placeholders: logger.info("User {} logged in", userId). The {} is a placeholder. If level is DEBUG, it skips string concatenation, saving CPU.
  • MDC: MDC.put("traceId", uuid) in a Servlet Filter. Every log line in that request will automatically include the traceId, making debugging across microservices possible.

🔄 Scrum Basics

  • Sprint: Fixed timebox (usually 2 weeks). Scope is locked once it starts.
  • Daily Standup: 15 mins max. 3 questions: What did I do? What will I do? Blockers? Not a status report to the manager.
  • Velocity: Total story points completed per sprint. Used to predict future capacity. Don't use it to measure individual performance.
  • DoD: Definition of Done. Code reviewed, unit tested, deployed to Staging, documented.

2. DB Connection Failed Is Docker running? Check properties URL/Password. Is VPN on?
3. Dependency Conflict Run mvn dependency:tree. Use <exclusions> to remove bad transitive dependencies.

☕ Core Java & Spring

✅ Code Submission Checklist

📦 Dependency Management

  • Maven vs Gradle: Maven uses rigid XML (pom.xml). Gradle uses Groovy/Kotlin DSL, is faster, and allows custom logic.
  • Scopes: compile (default), provided (needed to compile, but server provides it, e.g., Servlet API), test (JUnit).
  • Starters: spring-boot-starter-web bundles Tomcat, Jackson, Spring MVC automatically.
  • BOM (Bill of Materials): Import spring-boot-dependencies BOM in <dependencyManagement> to ensure all Spring modules use compatible versions without specifying versions manually.

🗃️ Basic SQL & JPA

  • Entity: @Entity, @Id, @GeneratedValue(strategy = GenerationType.IDENTITY).
  • Column Mapping: @Column(name = "user_name", nullable = false, length = 50).
  • Joins: @OneToMany, @ManyToOne. Always use FetchType.LAZY for OneToMany to prevent loading the whole DB into memory.
  • LazyInitializationException: Occurs if you access a lazy relation outside of a transaction (e.g., in the view layer). Fix: Fetch the data inside the service layer using JOIN FETCH.

🧪 Unit Testing Basics

  • Mockito: @Mock creates a dummy. @InjectMocks injects mocks into the class under test.
  • Stubbing: when(repo.findById(1L)).thenReturn(Optional.of(user)).
  • AAA Pattern: Arrange (setup data), Act (call method), Assert (check result).
  • Golden Rule: Never mock data structures (List, String). Only mock external boundaries (Database, APIs).

📬 Postman & API Testing

  • Environments: Save variables like {{base_url}} and {{token}} to switch between Local/Staging/Prod with one click.
  • Tests Tab: Write JS to auto-verify: pm.response.to.have.status(200);
  • Collection Runner: Run a sequence of API calls (e.g., Create User -> Get Token -> Fetch Profile) automatically to test flows.

📄 Pagination & Sorting

  • Spring Data: Pass Pageable pageable to method. Create via PageRequest.of(page, size, sort). Note: Page 0 is the first page.
  • Why: Don't load 1M records into RAM (OutOfMemoryError). Load 20 at a time.
  • Keyset Pagination: For massive datasets, use WHERE id > last_id LIMIT 20 instead of OFFSET. Offset requires the DB to scan and discard rows, getting exponentially slower on page 1000+.

💾 Database Transactions

  • @Transactional: Default Propagation: REQUIRED (Join existing tx or create new). Rollback happens automatically for RuntimeException, but NOT for checked exceptions (unless you specify rollbackFor = Exception.class).
  • Isolation: READ_COMMITTED (default, prevents dirty reads) vs SERIALIZABLE (prevents phantom reads, but locks tables, killing performance).
  • Locking: @Lock(LockModeType.PESSIMISTIC_WRITE) on repository method forces DB to lock the row until tx ends.
  • Pitfall: Never call a @Transactional method from within the *same class*. Spring uses AOP proxies; internal calls bypass the proxy, so the transaction won't actually open.

🧶 JSON & Jackson

  • Annotations: @JsonProperty("user_id"), @JsonIgnore (hide passwords), @JsonInclude(NON_NULL) (cleaner JSON response).
  • Custom Serializer: Implement StdSerializer<T> for complex logic (e.g., encrypting a field before sending).
  • @JsonView: Used to return different fields for the same DTO based on the endpoint (e.g., Public view hides internal ID, Admin view shows it).

✨ Clean Code Principles

  • Boy Scout Rule: Leave the code cleaner than you found it.
  • DRY: Don't Repeat Yourself. Extract common logic to private methods.
  • YAGNI: You Aren't Gonna Need It. Don't build abstractions for future features that haven't been requested yet. Premature optimization is the root of all evil.
  • Law of Demeter: user.getAddress().getCity().getName() is bad (tight coupling). user.getCityName() is good.

🔒 Security Essentials

  • OWASP Top 10: Injection, Broken Auth, XSS.
  • Passwords: Use BCrypt (automatically handles salting). Never MD5 or SHA-1.
  • JWT: Stateless auth. Short expiration (15 mins) + Long-lived Refresh Token (7 days). Store in HttpOnly cookie, NOT LocalStorage (prevents XSS theft).

⚠️ Exception Handling

  • Global Handler: Use @ControllerAdvice + @ExceptionHandler to catch exceptions globally instead of try-catch in every controller.
  • Never Swallow: Don't do catch (Exception e) { }. At least log it.
  • Error Codes: Use Enums for error codes (e.g., ERR_USER_NOT_FOUND) instead of hardcoded strings so frontend can switch on them easily.

🗂️ Java Collections

  • HashMap: O(1) lookup. You MUST implement equals() & hashCode() correctly. If you use a mutable field (like age) in hashCode, the map will "lose" your object when the field changes.
  • Concurrency: ConcurrentHashMap uses lock stripping (locks segments, not the whole map). Avoid Hashtable (locks everything, very slow).

⚔️ Code Review Dynamics

I disagree with a comment Reply: "I chose approach Y because of performance reason Z (see benchmark link). What do you think?"

🧪 Testing Strategies

  • Unit: Mock external deps (@MockBean). Fast.
  • Integration: Real DB (@DataJpaTest). Slower.
  • Golden Rule: Don't test private methods. Test the public behavior that uses the private method.

🏛️ Monolith vs. Microservices

  • Monolith: Easier start. Shared DB. Simple deployment.
  • Microservices: Independent deployment. Own DB. High network complexity.
  • Modular Monolith: Strict package boundaries in one JAR (e.g., com.app.order cannot access com.app.inventory). Best of both worlds for mid-size.

🌐 REST API Standards

  • Codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found.
  • Versioning: /api/v1/resource.
  • HATEOAS: (Hypermedia as the Engine of Application State). Returning links to next actions in the JSON response (e.g., "next": "/api/users?page=2"). Often skipped but technically required for true REST.

🧩 Design Patterns

  • Strategy: Swap algorithms at runtime (e.g., DiscountStrategy with ChristmasDiscount implementation).
  • Builder: Clean object creation when a class has many required/optional fields.
  • Template Method: Define skeleton in base class, let subclasses override steps (e.g., processOrder() steps).

🔍 Database Indexing

  • When: Columns frequently used in WHERE, JOIN, ORDER BY.
  • Downside: Slows down INSERT/UPDATE because the index must be updated too.
  • Composite Rule: INDEX(a, b). DB can search on (a) or (a, b), but NOT just (b). Left-most prefix rule.

⚙️ Spring Profiles & Configs

  • Files: application-dev.properties.
  • Activation: spring.profiles.active=prod via Env Var.
  • Secrets: Use Env Vars or HashiCorp Vault. NEVER hardcode passwords in properties files committed to Git.

⏱️ Scheduled Tasks

  • Usage: @Scheduled(cron = "0 0 12 * * ?") (Noon daily).
  • Drawback: If app scales to 2 pods, the job runs twice. Fix: Use K8s CronJob, or Quartz + DB lock to ensure only one node executes.

🚦 Rate Limiting

  • Algorithms: Token Bucket (allows short bursts up to capacity), Leaky Bucket (smooths out rate strictly).
  • Implementation: Use Bucket4j. For distributed apps, store bucket state in Redis so all pods share the same limit.
  • Headers: Return X-RateLimit-Remaining so clients know when to back off.

🔄 API Versioning

  • URI: /api/v1/users (Easy to understand, cacheable).
  • Header: Accept: application/vnd.myapi.v2+json (Clean URL, harder to test in Postman).
  • Deprecation: Keep V1 for 6 months. Return Warning: 299 - "Deprecated API" header with sunset date.

📊 Advanced Jira (JQL)

  • Operators: =, IN, WAS (for workflow transitions).
  • Examples: assignee = currentUser() AND sprint in openSprints()
  • Overdue: duedate < now() AND status != Done

⚙️ JVM Internals

  • Generations: Young Gen (short-lived objects, minor GC) vs Old Gen (long-lived, major GC/Stop-The-World).
  • GC Algorithms: G1GC (default in Java 9+, balanced). ZGC (Java 15+, sub-millisecond pauses, great for >16GB heaps).
  • Tuning: Don't guess. Take a heap dump (-XX:+HeapDumpOnOutOfMemoryError) and analyze with Eclipse MAT to find the exact object leaking memory.

⚡ Caching Strategies

  • Tools: Redis (Distributed, persistent), Caffeine (Local, ultra-fast, no network overhead).
  • Cache-Aside: Check Cache -> Miss -> DB -> Update Cache.
  • Invalidation: Time-based (TTL) vs Event-based (Publish update event to clear cache instantly).
  • Stampede: Cache expires, 1000 requests hit DB simultaneously. Fix: Use distributed locks or random TTL offset (e.g., TTL + random(0-60)s).

📨 Async Processing

  • Kafka: Topics, Partitions (parallelism), Consumer Groups (load balancing).
  • DLQ: Dead Letter Queue for messages that failed 3+ times. Don't drop them silently.
  • Exactly-Once: Very hard to achieve in distributed systems. Usually settle for "At-least-once" delivery + Idempotency in the consumer.

🚀 CI/CD & Automation

  • Strategies: Blue/Green (switch traffic instantly), Canary (route 5% traffic to new version, monitor errors, then 100%).
  • GitOps: ArgoCD watches Git repo and auto-applies K8s manifests. Git is the single source of truth.

🚨 Crisis Management

Client Angry (P0) 1. Acknowledge. 2. Communicate ETA. 3. Fix/Rollback. 4. Retro (MUST be Blameless—focus on the system, not "Who did it").

🚀 Performance Tuning

  • Tools: JProfiler, Java Flight Recorder (JFR - built into JDK), Gatling (Load Testing).
  • Metrics: High CPU (bad algo/loop), High Memory (leak or heap too small), High I/O Wait (DB latency).

🌐 Microservices Patterns

  • Circuit Breaker: Resilience4j. States: Closed (normal) -> Open (failing fast, not hitting downstream) -> Half-Open (testing if downstream recovered).
  • Saga: Choreography (events fired sequentially) vs Orchestration (central controller tells services what to do).

🔥 Real-time Scenarios

1. Outage Generate Thread Dump (jstack <pid>). Look for "BLOCKED" threads waiting on DB locks.
2. Deadlock Thread 1 locks A waits for B. Thread 2 locks B waits for A. Fix: Always acquire locks in the same global order.

⚙️ Java Concurrency

  • Executors: Manage thread pools. Never use new Thread() manually (unbounded thread creation crashes the JVM).
  • Virtual Threads (Java 21): Executors.newVirtualThreadPerTaskExecutor(). Great for I/O bound tasks (DB calls, HTTP calls). Do NOT use for CPU-bound tasks (image processing)—you will starve the OS CPU.

🔐 Spring Security Deep Dive

  • Filter Chain: SecurityFilterChain bean replaces deprecated adapter.
  • Method Security: @PreAuthorize("hasRole('ADMIN')") at service layer.
  • Session vs JWT: Session (stateful, easy to revoke, hard to scale). JWT (stateless, highly scalable, hard to revoke immediately before expiry).

💾 Data Modeling Strategy

  • Normalization: ACID compliant. Reduces redundancy. Good for transactional systems.
  • Denormalization: Duplicates data. BASE compliant. Good for Analytics/NoSQL where read speed is critical.
  • Sharding: Split large DBs by hash (e.g., User ID % 100) across multiple servers.

🚪 API Gateway Patterns

  • BFF: Backend for Frontend (Different gateways for Web vs Mobile).
  • Composition: Gateway aggregates responses from multiple microservices.
  • Sidecar: Envoy proxy pattern (e.g., Istio service mesh) vs centralized gateway.

📡 Event-Driven Architecture

  • Decoupling: Services talk via events, not synchronous HTTP calls.
  • Outbox Pattern: Write event to DB "outbox" table in same TX as business data. Separate worker polls outbox and publishes to Kafka. Guarantees atomicity.
  • Schema Evolution: Use Avro/Protobuf with Schema Registry. Never break backward compatibility in event formats.

🏗️ System Design Concepts

  • CAP Theorem: During a network partition, choose Consistency (return error to user) or Availability (return stale data). You cannot have both.
  • PACELC: Extension of CAP for normal operations (Latency vs Consistency).
  • CQRS: Separate read/write models. Writes go to Postgres. Reads go to Elasticsearch.

🏛️ Domain-Driven Design (DDD)

  • Ubiquitous Language: If business says "Cargo", code must say "Cargo" not "Item".
  • Bounded Context: "Shipping" context has different meaning for "Package" than "Software" context.
  • Domain Events: "OrderPlaced", "PaymentFailed". Trigger side effects without tight coupling.

💰 Cost Optimization (FinOps)

  • Right-sizing: Downgrade instances that sit at 10% CPU.
  • Spot Instances: 90% cheaper for stateless workers. They can be terminated anytime by AWS, so your app must be resilient to pod death.
  • Storage: Move old logs from S3 Standard to S3 Glacier (much cheaper, takes hours to retrieve).
